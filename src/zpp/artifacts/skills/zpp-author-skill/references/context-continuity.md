# Context continuity

Externalize the current contract before collecting more detail. For OpenSpec
clarification, write the established overview and capability deltas first;
then investigate or interview; then revise the same artifacts to align with new
evidence. Never delay all durable recording until after a long interrogation.

Record only the state owned by the current stage. Preserve settled decisions,
explicit deferrals, unresolved owner choices, evidence, and the next owning
handoff. Do not turn temporary utility planning into canonical specs, duplicate
Gherkin examples in OpenSpec, or use zmem as a live task log.

When context is refreshed, resume from canonical OpenSpec, the active change,
the current feature contracts, relevant zmem history, and repository state.
Reconcile them before taking new action; do not reconstruct policy from memory.
